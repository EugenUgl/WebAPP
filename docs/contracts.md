# 📜 Контракты взаимодействия

Документ описывает правила общения между сервисами. Любое изменение здесь требует синхронизации команд разработки.

## 1. HTTP Контракты (Синхронные)

Клиент общается с системой **только** через API Gateway (внешний порт 8080).

| Метод | Путь (через Gateway) | Назначение | Ответ (Успех) |
| :--- | :--- | :--- | :--- |
| `GET` | `/` | Главная страница (отдает `frontend-service`) | `200 OK`, HTML |
| `GET` | `/register` | Форма регистрации | `200 OK`, HTML |
| `POST` | `/register` | Обработка регистрации | `302 Redirect` на `/login` |
| `GET` | `/login` | Форма входа | `200 OK`, HTML |
| `POST` | `/login` | Аутентификация | `302 Redirect` на `/dashboard` |
| `GET` | `/dashboard` | Личный кабинет (только для авторизованных) | `200 OK`, HTML |
| `GET` | `/logout` | Выход из системы | `302 Redirect` на `/login` |

## 2. Событийные Контракты (Асинхронные)

Взаимодействие через брокер **NATS JetStream**.

### Событие: `user.registered` (Регистрация пользователя)

*   **Издатель (Publisher):** `auth-backend`
*   **Подписчики (Subscribers):** `frontend-service` (и любые будущие сервисы)
*   **Транспорт:** NATS JetStream
*   **Stream Name:** `USER_EVENTS`
*   **Subject:** `user.registered`

**Схема полезной нагрузки (Payload JSON):**
```json
{
  "username": "string"
}
```

*Примечание:* Сообщение сохраняется на диск в NATS JetStream. Подписчики используют `Durable Consumer` (например, `frontend_consumer`), чтобы гарантированно получить события даже после перезапуска контейнера.
